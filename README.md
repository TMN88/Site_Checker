# Site_Checker для OpenWrt 24.x и 25.x

LuCI-панель для проверки доступности сайтов с самого роутера OpenWrt и управления переключением AmneziaWG (AWG) в Podkop.

## Возможности

- LuCI: **Services → Site_Checker**.
- Проверка HTTP/HTTPS через сетевую конфигурацию роутера: DNS, маршрутизацию и действующие правила.
- Статус, задержка и HTTP-код; редактируемый список до 30 URL; автообновление каждые 60 секунд.
- Встроенная панель **AWG / Podkop VPN Failover** сразу под таблицей сайтов.
- Отображение статуса failover, автозапуска, выбранного VPN-интерфейса и готовности runtime Podkop.
- Действия AWG: обновить статус, проверить все AWG-интерфейсы, просмотреть логи и настройки, включить автозапуск и запустить сервис, перезапустить, остановить и отключить автозапуск.
- В интерфейсе разрешены только фиксированные команды управления; произвольное выполнение shell-команд из браузера не предусмотрено.

## Поддерживаемые версии OpenWrt

- **OpenWrt 24.x** — установщик использует `opkg`.
- **OpenWrt 25.x** — установщик использует `apk` (включая ветку 25.12).

Установщик выбирает пакетный менеджер автоматически, устанавливает необходимые `luci-base` и `curl`, проверяет загруженные shell-скрипты и совместим с BusyBox: вместо GNU `install` используются `cp` и `chmod`.

Совместимость зависит также от конкретной сборки и состава LuCI. Установка на реальном устройстве и фактическое переключение AWG должны быть проверены на вашем роутере.

## Установка

Выполни по SSH от `root`:

```sh
wget -O /tmp/site-checker-install.sh https://cdn.jsdelivr.net/gh/TMN88/Site_Checker@8740e588f5bdab1e07ab26e94ea4cc60ff311a44/install.sh && sh /tmp/site-checker-install.sh
```

Если установлен `curl`, можно скачать установщик так:

```sh
curl -fsSL https://cdn.jsdelivr.net/gh/TMN88/Site_Checker@8740e588f5bdab1e07ab26e94ea4cc60ff311a44/install.sh -o /tmp/site-checker-install.sh && sh /tmp/site-checker-install.sh
```

После установки открой **LuCI → Services → Site_Checker**.

## Первичная настройка AWG failover

Встроенный модуль основан на [SVTagan/podkop-vpn-failover](https://github.com/SVTagan/podkop-vpn-failover), версия 0.1.3. Исходный код включён по лицензии MIT; лицензионный текст сохранён в `files/PODKOP-VPN-FAILOVER-LICENSE`. Это независимый сторонний проект, не являющийся частью Podkop.

Для работы необходимы Podkop в VPN-режиме, sing-box и интерфейсы AmneziaWG с именами `awg*` и протоколом `amneziawg`. Текущий основной интерфейс берётся из `podkop.main.interface`.

**При первой установке failover оставляется выключенным.** Это сделано намеренно, чтобы не менять маршрут трафика без проверки. В панели:

1. Нажми **«Проверить все AWG»** и убедись, что нужные туннели проходят health-check.
2. Посмотри **«Обновить статус»** и текущий интерфейс Podkop.
3. Только после проверки нажми **«Включить автозапуск и запустить»** и подтверди действие.

Механизм upstream проверяет реальный HTTPS-запрос через конкретный интерфейс, использует порог из трёх ошибок подряд, дважды проверяет резерв и штатно перезагружает Podkop после переключения. После старта действует grace period 120 секунд. Эти параметры заданы внутри поставляемого worker-файла.

Кнопка **«Остановить и отключить автозапуск»** останавливает автоматическое переключение; она не отключает сами интерфейсы AWG. Тестирование всех интерфейсов может занимать некоторое время в зависимости от их количества и тайм-аутов health-check.

## Сборка IPK/APK из исходников

Папка `package/luci-app-sitecheck` содержит Makefile и все файлы приложения, включая AWG worker. Скопируй её в `package/` подходящего SDK для своего target/subtarget и собери:

```sh
make package/luci-app-sitecheck/compile V=s
```

Нужен SDK, соответствующий архитектуре и версии OpenWrt, для которой выполняется сборка. Готовые IPK/APK-артефакты в репозитории не публикуются.

## Удаление

Если приложение установлено установщиком выше:

```sh
sh /tmp/site-checker-install.sh --uninstall
```

Файл `/etc/config/sitecheck` сохраняется. Если `podkop-vpn-failover` существовал до установки Site_Checker, установщик не считает его своим и при удалении панели оставляет этот компонент на месте. Если failover был впервые установлен самим Site_Checker, он удаляется вместе с панелью после остановки и отключения его сервиса.

## Замечания

- Недоступность сайта не обязательно означает блокировку: возможны проблемы DNS, TLS, маршрута, firewall или самого сервера.
- Проверка сайта выполняется с роутера и не гарантирует, что трафик клиентов проходит точно по тому же пути.
- Не включай автоматический failover, пока не проверишь оба AWG-туннеля и корректность текущей конфигурации Podkop.
